§

먼저 알아야 할 4가지

개별 컴포넌트를 외우기 전에 이 네 가지를 이해하면 나머지는 대부분 유추됩니다. Gradio 앱은 결국 함수 하나를 UI 컴포넌트로 감싸는 일입니다.

① Interface vs Blocks — 얼마나 커스텀할 것인가

gr.Interface는 "함수 하나 + 입력 스펙 + 출력 스펙"만 주면 UI를 자동으로 만들어줍니다. 빠르지만 레이아웃 자유도가 낮습니다. gr.Blocks는 컴포넌트를 with 블록 안에 직접 배치하고 이벤트를 하나씩 연결하는 저수준 API로, 복잡한 대시보드·멀티스텝 UI에는 사실상 필수입니다.

예시 코드

# Interface — 빠른 프로토타입
import gradio as gr

def greet(name):
    return f"Hello, {name}!"

demo = gr.Interface(fn=greet, inputs="text", outputs="text")
demo.launch()

# Blocks — 레이아웃을 직접 제어
with gr.Blocks() as demo:
    name = gr.Textbox(label="이름")
    output = gr.Textbox(label="결과")
    btn = gr.Button("실행")
    btn.click(fn=greet, inputs=name, outputs=output)
demo.launch()
데모/프로토타입은 Interface로 시작하고, 버튼이 2개 이상이거나 컴포넌트 간 배치·조건부 표시가 필요해지는 순간 Blocks로 옮기는 것이 자연스러운 흐름입니다.

② 컴포넌트 = 입력이자 출력

Gradio 컴포넌트(Textbox, Image, Slider …)는 고정된 "입력용"·"출력용"이 따로 있지 않습니다. 같은 클래스를 inputs=에 넣으면 사용자가 값을 넣는 위젯이 되고, outputs=에 넣으면 함수 반환값을 표시하는 자리가 됩니다. 함수의 파라미터 순서와 inputs 리스트 순서, 반환값 순서와 outputs 리스트 순서가 각각 1:1로 매칭됩니다.

예시 코드

def bmi(weight, height):
    h = height / 100
    return round(weight / (h * h), 1), "정상" if 18.5 <= weight/(h*h) <= 25 else "주의"

demo = gr.Interface(
    fn=bmi,
    inputs=[gr.Number(label="몸무게(kg)"), gr.Number(label="키(cm)")],
    outputs=[gr.Number(label="BMI"), gr.Textbox(label="판정")],
)
함수 반환값이 하나뿐인데 outputs를 리스트로 감싸지 않는 등 개수가 맞지 않으면 ValueError가 납니다. 반환값 1개 ↔ 컴포넌트 1개는 리스트 없이 써도 되지만, 2개 이상부터는 순서가 있는 리스트/튜플로 정확히 맞춰야 합니다.

③ 이벤트 리스너 — fn / inputs / outputs 삼각형

btn.click(fn, inputs, outputs)처럼 컴포넌트의 이벤트 메소드는 항상 이 세 인자를 중심으로 동작합니다. 이벤트가 발생하면 inputs에 나열된 컴포넌트들의 현재 값을 모아 fn에 넘기고, 반환값을 outputs 컴포넌트에 순서대로 채워 넣습니다.

예시 코드

with gr.Blocks() as demo:
    a = gr.Number(label="a")
    b = gr.Number(label="b")
    result = gr.Number(label="합계")
    btn = gr.Button("더하기")
    btn.click(fn=lambda x, y: x + y, inputs=[a, b], outputs=result)
    # 입력값이 바뀔 때마다 자동 계산하고 싶다면 .change로도 같은 fn을 연결
    a.change(fn=lambda x, y: x + y, inputs=[a, b], outputs=result)
    b.change(fn=lambda x, y: x + y, inputs=[a, b], outputs=result)
inputs=[](빈 리스트)나 outputs=None도 유효합니다. 입력 없이 매번 랜덤 값을 반환하거나, 화면에 아무것도 갱신하지 않고 사이드이펙트(로그 저장 등)만 실행하는 이벤트를 만들 때 씁니다.

④ State — 요청 사이에 값을 기억하기

일반 컴포넌트 값은 매 이벤트마다 브라우저에서 서버로 다시 전송되지만, 화면에 보이지 않으면서 세션별로 값을 유지하고 싶다면 gr.State를 씁니다. 기본적으로 브라우저 탭(세션) 단위로 격리되어 다른 사용자와 값이 섞이지 않습니다.

예시 코드

with gr.Blocks() as demo:
    count = gr.State(0)              # 화면에 보이지 않는 세션별 카운터
    label = gr.Textbox(label="클릭 수")
    btn = gr.Button("클릭")

    def increment(c):
        c += 1
        return c, f"총 {c}번 클릭"
    btn.click(fn=increment, inputs=count, outputs=[count, label])
서버 재시작 없이 여러 사용자가 동시 접속해도 각자의 count는 독립적으로 유지됩니다. 모든 사용자가 공유하는 전역 상태가 필요하면 gr.State 대신 파이썬 모듈 전역 변수나 외부 DB를 씁니다.

#02

gr.Interface()

함수 하나를 감싸서 입력·출력 UI를 자동 생성합니다. inputs/outputs에 문자열 축약형("text", "image" …)이나 컴포넌트 인스턴스를 넣을 수 있습니다.

시그니처

gr.Interface(fn, inputs, outputs, examples=None, title=None, description=None, cache_examples=False, flagging_mode="manual")

파라미터

파라미터설명기본값 / 옵션
fn 필수실행할 파이썬 함수—
inputs / outputs 필수컴포넌트(문자열 축약 또는 인스턴스) 또는 그 리스트. 입력 없는 함수는 inputs=None—
examples예시 입력값 리스트. 클릭하면 자동으로 채워짐None
cache_examplesTrue면 앱 로드 시 examples를 미리 실행해 캐싱False
flagging_mode사용자가 결과를 "플래그"로 저장할 수 있는 버튼 표시 여부"manual" / "never", "auto"

예시 코드

import gradio as gr

def to_upper(text):
    return text.upper()

demo = gr.Interface(
    fn=to_upper,
    inputs=gr.Textbox(label="입력", placeholder="소문자를 입력하세요"),
    outputs=gr.Textbox(label="결과"),
    examples=["hello world", "gradio"],
    title="대문자 변환기",
)
demo.launch()
입력과 출력이 여러 개면 리스트로, 함수가 다중 값을 return a, b처럼 반환하면 outputs도 그 순서에 맞춘 리스트로 넘기세요.

gr.ChatInterface()

전용

채팅형 UI를 위한 고수준 래퍼입니다. fn이 (message, history)를 받아 응답 문자열을 반환하도록 작성하면 메시지 입력창·전송 버튼·대화 이력 렌더링을 알아서 처리합니다. 자세한 스트리밍 사용법은 F. 스트리밍과 채팅 참고.

시그니처

gr.ChatInterface(fn, type="messages", examples=None, chatbot=None)

예시 코드

def respond(message, history):
    return f"당신은 "{message}"라고 말했습니다"

demo = gr.ChatInterface(fn=respond, type="messages")
demo.launch()
history는 type="messages" 기준 [{"role": "user", "content": ...}, {"role": "assistant", "content": ...}, ...] 형태의 리스트입니다.

gr.Examples()

Interface의 examples 인자와 달리 Blocks 안에서 독립적으로 예시 표를 배치할 때 씁니다. 클릭하면 지정한 입력 컴포넌트들에 값을 채웁니다.

시그니처

gr.Examples(examples, inputs, outputs=None, fn=None, cache_examples=False)

예시 코드

with gr.Blocks() as demo:
    inp = gr.Textbox(label="프롬프트")
    out = gr.Textbox(label="결과")
    gr.Examples(examples=["고양이 그림", "우주 배경"], inputs=inp)
    inp.submit(fn=lambda t: t[::-1], inputs=inp, outputs=out)

컴포넌트 문자열 축약형

Interface에서만 쓸 수 있는 표기로, 빠른 프로토타입에 유용합니다. Blocks에서는 항상 실제 클래스 인스턴스를 씁니다.

축약형실제 컴포넌트
"text"gr.Textbox()
"number"gr.Number()
"image"gr.Image()
"audio"gr.Audio()
"checkbox"gr.Checkbox()

Blocks와 레이아웃

6 functions

컴포넌트를 화면 어디에, 어떤 순서로 배치할지 제어하는 컨테이너들입니다. 기본 배치는 세로로 쌓기이며, Row로 감싸면 가로로 나열됩니다.

#01

gr.Blocks()

모든 커스텀 Gradio 앱의 시작점. with gr.Blocks() as demo: 블록 안에서 선언한 컴포넌트가 위에서 아래로 배치되고, 블록을 벗어난 뒤 demo.launch()로 실행합니다.

시그니처

gr.Blocks(theme=None, css=None, title="Gradio")

예시 코드

with gr.Blocks(title="내 앱") as demo:
    gr.Markdown("# 계산기")
    a, b = gr.Number(label="a"), gr.Number(label="b")
    out = gr.Number(label="결과")
    gr.Button("더하기").click(lambda x, y: x + y, [a, b], out)

demo.launch()
demo라는 변수명은 관례일 뿐 강제 사항은 아니지만, Hugging Face Spaces에 배포할 때 app.py의 최상위 변수명을 관례적으로 demo로 맞춰두면 협업 시 헷갈리지 않습니다.
#06

gr.Row() · gr.Column()

Row 안의 컴포넌트는 가로로, Column 안은 세로로 배치됩니다. 중첩해서 그리드 레이아웃을 구성하는 것이 가장 흔한 패턴입니다.

예시 코드

with gr.Blocks() as demo:
    with gr.Row():
        with gr.Column(scale=1):
            img_in = gr.Image(label="입력 이미지")
            btn = gr.Button("변환")
        with gr.Column(scale=2):
            img_out = gr.Image(label="결과")
Column(scale=2)는 scale=1인 형제보다 2배 넓게 차지합니다. 픽셀 대신 상대 비율로 반응형 레이아웃을 짤 때 씁니다.
#13

gr.Tabs() · gr.Tab()

여러 화면을 탭으로 전환합니다. 서로 다른 기능(예: 텍스트 생성 탭 / 이미지 생성 탭)을 한 앱에 묶을 때 씁니다.

예시 코드

with gr.Blocks() as demo:
    with gr.Tabs():
        with gr.Tab("텍스트"):
            gr.Textbox(label="입력")
        with gr.Tab("이미지"):
            gr.Image(label="업로드")

gr.Accordion() · gr.Group()

Accordion은 클릭해서 펼치고 접는 섹션(고급 옵션 숨기기에 자주 사용), Group은 여러 컴포넌트 사이의 여백을 없애 시각적으로 하나로 묶습니다.

예시 코드

with gr.Blocks() as demo:
    gr.Textbox(label="프롬프트")
    with gr.Accordion("고급 설정", open=False):
        gr.Slider(0, 1, label="temperature")
        gr.Slider(1, 100, label="max_tokens")

@gr.render

신규

입력값에 따라 컴포넌트 개수 자체를 동적으로 바꿔야 할 때 씁니다(예: 리스트 길이만큼 항목 렌더링). 함수가 다시 호출될 때마다 데코레이터가 지정한 컨테이너 안을 통째로 다시 그립니다.

예시 코드

with gr.Blocks() as demo:
    n = gr.Slider(1, 5, step=1, label="항목 수")

    @gr.render(inputs=n)
    def show_boxes(count):
        for i in range(int(count)):
            gr.Textbox(label=f"항목 {i+1}")
Gradio 4.x 후반에 추가된 비교적 신규 기능이므로, 오래된 버전(3.x)에는 없습니다.

컴포넌트 표시/활성 제어 (visible · interactive)

이벤트 핸들러가 컴포넌트 자체를 새로 반환하면 visible, interactive 같은 속성을 실행 중에 바꿀 수 있습니다.

예시 코드

with gr.Blocks() as demo:
    chk = gr.Checkbox(label="고급 옵션 보기")
    adv = gr.Textbox(label="고급 옵션", visible=False)
    chk.change(lambda v: gr.Textbox(visible=v), inputs=chk, outputs=adv)

gr.Textbox()

한 줄/여러 줄 텍스트 입력. 가장 기본적인 컴포넌트이며 출력용으로도 똑같이 씁니다.

시그니처

예시 코드

prompt = gr.Textbox(
    label="프롬프트",
    lines=3,
    placeholder="무엇을 그려드릴까요?",
    info="영어로 입력하면 더 정확합니다",
)

gr.Slider()

최소~최대 범위의 숫자를 드래그로 선택합니다. temperature, top_p 같은 모델 하이퍼파라미터 UI에 표준으로 쓰입니다.

gr.Slider(minimum=0, maximum=100, value=None, step=None, label=None)

gr.File()

파일을 업로드하면 서버 측 임시 경로(문자열) 또는 type="binary"일 때 바이트를 함수에 전달합니다.

예시 코드

def read_lines(file_path):
    with open(file_path) as f:
        return len(f.readlines())

gr.Interface(fn=read_lines, inputs=gr.File(label="텍스트 파일"), outputs="number")
#07

gr.Image() (입력)

업로드·드래그·sources=["webcam"]이면 웹캠 촬영까지 지원합니다. 함수에는 기본적으로 numpy.ndarray(RGB)로 전달됩니다.

시그니처

gr.Image(type="numpy", sources=["upload", "webcam", "clipboard"])

예시 코드

import numpy as np

def to_grayscale(img: np.ndarray):
    return np.mean(img, axis=2).astype(np.uint8)

gr.Interface(fn=to_grayscale, inputs=gr.Image(type="numpy"), outputs="image")
type="pil"·"numpy"·"filepath" 셋 중 하나로 명시해두지 않으면 라이브러리 버전에 따라 기본값이 달라질 수 있어 함수 안 타입 처리가 꼬이기 쉽습니다. 항상 명시적으로 지정하세요.

gr.Markdown() · gr.HTML()

정적 설명 텍스트나 함수가 생성한 서식 있는 결과(제목, 표, 링크 등)를 보여줍니다. Markdown은 마크다운 문법을, HTML은 원시 HTML을 그대로 렌더링합니다.

예시 코드

gr.Markdown("## 결과 요약\n- 정확도: **92%**\n- 소요 시간: 1.2초")
gr.HTML()에 사용자 입력을 그대로 넣으면 XSS 위험이 있습니다. 신뢰할 수 없는 문자열을 표시할 때는 gr.Textbox나 gr.Markdown(자동 이스케이프)을 우선 고려하세요.

gr.Image() (출력) · gr.Gallery()

단일 이미지는 Image, 여러 장을 그리드로 보여줄 때는 Gallery를 씁니다. 함수는 PIL Image, numpy 배열, 파일 경로 중 무엇을 반환해도 됩니다.

예시 코드

def variations(img):
    return [img.rotate(a) for a in (0, 90, 180, 270)]

gr.Interface(fn=variations, inputs=gr.Image(type="pil"), outputs=gr.Gallery(columns=4))

gr.Audio() · gr.Video()

오디오/비디오 파일을 업로드받거나 재생합니다. Audio는 type="numpy"일 때 (sample_rate, data) 튜플로 전달됩니다.

예시 코드

def speed_up(audio):
    sr, data = audio
    return (sr * 2, data)   # 재생 속도 2배(샘플레이트 조작)

gr.Interface(fn=speed_up, inputs=gr.Audio(type="numpy"), outputs=gr.Audio())

gr.Dataframe()

pandas DataFrame, 2차원 리스트, numpy 배열을 편집 가능한 표로 보여줍니다. 셀 직접 수정도 지원해 입력으로도 자주 쓰입니다.

import pandas as pd

def add_total(df: pd.DataFrame):

gr.Interface(fn=add_total, inputs=gr.Dataframe(headers=["국어", "수학"]), outputs=gr.Dataframe())

gr.Plot()

Matplotlib Figure, Plotly Figure 등을 그대로 반환하면 인터랙티브하게 렌더링합니다.

예시 코드

import matplotlib.pyplot as plt

def plot_square(n):
    fig, ax = plt.subplots()
    ax.plot(range(n), [i**2 for i in range(n)])
    return fig

gr.Interface(fn=plot_square, inputs=gr.Slider(1, 20, step=1), outputs=gr.Plot())

#03

.click() · .change() · .submit() 등 이벤트 리스너

거의 모든 컴포넌트가 자신에게 맞는 이벤트 메소드를 가집니다. 공통 인자는 fn/inputs/outputs이고, 추가로 실행 방식을 제어하는 옵션이 있습니다.

이벤트발생 컴포넌트발생 시점
.click()Button버튼 클릭
.change()대부분의 컴포넌트값이 바뀔 때마다(타이핑 중에도)
.submit()Textbox 등포커스 상태에서 Enter
.select()Dataframe, Gallery 등항목/셀 선택
.upload()File, Image, Audio파일 업로드 완료

파라미터

파라미터설명기본값
show_progress실행 중 로딩 스피너 표시 방식"full" / "minimal", "hidden"
queue대기열 사용 여부(무거운 GPU 함수는 반드시 True 권장)True
api_nameREST/Python 클라이언트로 이 이벤트를 호출할 때 쓸 이름None(자동)

예시 코드

search.change(fn=filter_results, inputs=search, outputs=table, show_progress="minimal")

이벤트 체이닝 — .then() · .success()

이벤트 리스너가 반환하는 객체에 .then()을 이어 붙이면, 앞 이벤트가 끝난 뒤 순차적으로 다음 함수를 실행합니다. 여러 단계 파이프라인(입력 검증 → 처리 → 로깅)에 씁니다.

예시 코드

btn.click(fn=validate, inputs=inp, outputs=status) \
   .then(fn=process, inputs=inp, outputs=result) \
   .then(fn=log_usage, inputs=[inp, result], outputs=None)
.success()는 .then()과 비슷하지만 앞 함수가 예외 없이 끝났을 때만 실행됩니다. 에러가 나도 항상 실행돼야 하는 정리 작업이 아니라면 .success()가 더 안전합니다.

#17

컴포넌트 속성 갱신 · gr.skip()

이벤트 핸들러가 값뿐 아니라 label, visible 등 속성까지 바꾸려면 해당 컴포넌트 클래스를 새 인자로 다시 생성해 반환합니다. 반환값을 아예 건너뛰고 화면을 그대로 두려면 gr.skip()을 반환합니다.

예시 코드

def maybe_update(x):
    if x < 0:
        return gr.skip()   # 화면 값을 바꾸지 않음
    return gr.Textbox(value=f"결과: {x}", label="성공")
과거 버전의 gr.update(...)도 여전히 동작하지만, 최신 Gradio는 컴포넌트 클래스를 직접 반환하는 방식을 권장합니다.
#20

gr.Progress()

오래 걸리는 함수 안에서 진행률 바를 갱신합니다. 함수 파라미터에 기본값으로 넣어두면 Gradio가 자동으로 주입합니다.

예시 코드

def long_task(n, progress=gr.Progress()):
    total = 0
    for i in progress.tqdm(range(n)):
        total += i
    return total

gr.Error()

함수 안에서 raise gr.Error("메시지")를 던지면 서버 로그에 스택트레이스를 남기는 대신 사용자에게 붉은 토스트 알림으로 메시지만 깔끔하게 보여줍니다.

예시 코드

def divide(a, b):
    if b == 0:
        raise gr.Error("0으로 나눌 수 없습니다")
    return a / b

#09

제너레이터 함수로 출력 스트리밍

이벤트에 연결한 함수가 return 대신 yield를 쓰면, 매번 값을 만들 때마다 UI가 즉시 갱신됩니다. LLM 토큰을 한 글자씩 흘려보내는 표준 패턴입니다.

예시 코드

import time

def stream_response(prompt):
    partial = ""
    for ch in "Gradio는 정말 빠릅니다.":
        partial += ch
        time.sleep(0.02)
        yield partial   # 매 반복마다 textbox가 갱신됨

gr.Interface(fn=stream_response, inputs="text", outputs="text")
여러 출력 컴포넌트가 있다면 yield a, b처럼 매번 전체 튜플을 반환해야 합니다. 하나만 바뀌었다고 나머지를 생략할 수 없습니다.

ChatInterface + 스트리밍

gr.ChatInterface의 fn도 제너레이터로 작성하면 챗봇 답변이 타이핑되듯 실시간으로 나타납니다. 실무 LLM 데모의 표준 형태입니다.

예시 코드

def respond_stream(message, history):
    reply = f"네, '{message}'에 대한 답변입니다."
    partial = ""
    for ch in reply:
        partial += ch
        yield partial

gr.ChatInterface(fn=respond_stream, type="messages").launch()

gr.Chatbot()

ChatInterface가 내부적으로 쓰는 채팅 로그 컴포넌트를 Blocks 안에서 직접 배치하고 싶을 때 씁니다 — 예: 채팅창 옆에 별도 사이드바를 두는 커스텀 레이아웃.

예시 코드

with gr.Blocks() as demo:
    chatbot = gr.Chatbot(type="messages")
    msg = gr.Textbox(label="메시지")

    def reply(message, history):
        history = history + [{"role": "user", "content": message}]
        history = history + [{"role": "assistant", "content": f"echo: {message}"}]
        return "", history

    msg.submit(fn=reply, inputs=[msg, chatbot], outputs=[msg, chatbot])

.launch()

개발용 웹 서버를 시작합니다. 스크립트 마지막 줄에 한 번만 호출합니다.

시그니처

demo.launch(server_name="127.0.0.1", server_port=None, share=False, debug=False)

파라미터

파라미터설명기본값
shareTrue면 72시간 유효한 공개 URL(gradio.live)을 생성해 외부에서 접속 가능False
server_name"0.0.0.0"으로 두면 같은 네트워크의 다른 기기에서도 접속 가능"127.0.0.1"
server_port포트 번호. 생략하면 7860부터 빈 포트 자동 탐색None
debugColab 등에서 에러를 셀 출력에 바로 표시False

예시 코드

demo.launch(server_name="0.0.0.0", server_port=7860, share=False)
share=True는 편리하지만 인증 없이 누구나 URL로 접근 가능합니다. 민감한 데이터를 다루는 앱이라면 auth=("user", "pw") 인자로 기본 인증을 추가하세요.

.queue()

여러 사용자가 동시에 무거운 함수(GPU 추론 등)를 요청할 때 순서대로 처리하도록 대기열을 켭니다. Blocks는 기본적으로 큐가 켜져 있고, 세밀한 동시성 제어가 필요할 때 명시적으로 호출합니다.

demo.queue(default_concurrency_limit=2).launch()   # 동시에 최대 2개 요청 처리
이벤트별로 동시성을 다르게 주고 싶다면 .click(..., concurrency_limit=1)처럼 이벤트 리스너 인자로도 지정할 수 있습니다.
