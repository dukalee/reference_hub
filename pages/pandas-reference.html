① 인덱스 — pandas가 NumPy와 다른 유일한 이유

ndarray는 위치로만 원소를 찾습니다. pandas 객체는 여기에 라벨(index/columns)이 붙습니다. 그리고 두 객체를 연산하면 pandas는 라벨을 기준으로 자동 정렬한 뒤 계산합니다. 이걸 모르면 "왜 갑자기 NaN이 생기지?"에서 반나절을 씁니다.

예시 코드

a = pd.Series([1, 2, 3], index=["x", "y", "z"])
b = pd.Series([10, 20, 30], index=["y", "z", "w"])
print(a + b)                      # 라벨 기준 정렬 → 겹치지 않는 x, w는 NaN
print(a.values + b.values)        # NumPy로 내리면 위치 기준
print(a.add(b, fill_value=0))     # 결측을 0으로 채우고 정렬
w NaN x NaN y 12.0 z 23.0 dtype: float64 [11 22 33] w 30.0 x 1.0 y 12.0 z 23.0 dtype: float64
인덱스가 의미 없는 상태(중간에 필터링해서 0,3,5처럼 구멍 난 정수 인덱스)에서 다른 프레임과 붙일 때 사고가 납니다. 붙이기 전에 reset_index(drop=True)로 정리하거나, 애초에 의미 있는 키를 set_index()로 올려 두세요.

② 라벨(.loc) vs 위치(.iloc)

선택 문법이 헷갈리는 이유는 두 체계가 공존하기 때문입니다. 규칙은 단순합니다 — .loc은 라벨, .iloc은 0부터 세는 위치. 그리고 .loc의 슬라이스는 끝을 포함하고, .iloc은 파이썬처럼 끝을 제외합니다.

예시 코드

s = pd.Series([10, 20, 30, 40], index=["a", "b", "c", "d"])
print(s.loc["a":"c"])    # 라벨 슬라이스 → c 포함(3개)
print(s.iloc[0:3])       # 위치 슬라이스 → 3 제외(3개)

s2 = pd.Series([10, 20, 30], index=[2, 0, 1])   # 정수 라벨 인덱스
print(s2.loc[2], s2.iloc[2])   # 라벨 2는 첫 값, 위치 2는 마지막 값
a 10 b 20 c 30 dtype: int64 a 10 b 20 c 30 dtype: int64 10 30
정수 라벨 인덱스에서 s[2]처럼 대괄호만 쓰면 라벨인지 위치인지 사람이 헷갈립니다. 실무 코드에서는 [] 단독 인덱싱을 피하고 항상 .loc / .iloc을 명시하세요. 라벨/위치를 섞어 쓰던 .ix는 pandas 1.0에서 완전히 제거됐습니다.

③ 결측값 — NaN, None, NaT, pd.NA

pandas의 결측은 dtype마다 표현이 다릅니다. 공통 규칙은 결측은 자기 자신과 같지 않다(np.nan != np.nan)는 것이고, 그래서 비교 연산이 아니라 isna()로 판정해야 합니다. 그리고 대부분의 집계 함수는 결측을 조용히 건너뜁니다.

표현등장하는 dtype비고
np.nanfloat64가장 흔함. 정수 열에 결측이 생기면 열 전체가 float으로 승격
NaTdatetime64 / timedelta64Not a Time
Noneobject파이썬 객체 열
pd.NAInt64 / boolean / str (nullable)pandas 3.0의 str dtype 기본 결측값

예시 코드

s = pd.Series([1, np.nan, 3])
print(s.sum(), s.mean(), s.count())   # 결측은 무시하고 계산
print(np.nan == np.nan, s.isna().sum())

ints = pd.Series([1, 2, None])                    # 정수인데 결측 → float 승격
nullable = pd.Series([1, 2, None], dtype="Int64") # nullable 정수 유지
print(ints.dtype, nullable.dtype)
print(nullable.sum())
4.0 2.0 2 False 1 float64 Int64 3
집계가 결측을 건너뛴다는 건 평균의 분모가 달라진다는 뜻입니다. mean()은 결측을 뺀 개수로 나눕니다. 결측을 0으로 취급하고 싶으면 반드시 fillna(0)을 먼저 하세요. sum()은 전부 결측이어도 기본값 0.0을 돌려주니, 그 구분이 필요하면 min_count=1을 주세요.

④ dtype — 성능과 버그가 동시에 결정되는 지점

열 하나가 곧 하나의 배열이고, 그 dtype이 메모리·속도·연산 결과를 전부 결정합니다. pandas 3.0부터 문자열 열은 object가 아니라 전용 str dtype으로 추론됩니다.

⑤ Copy-on-Write — pandas 3.0의 가장 큰 변화

pandas 3.0부터 모든 인덱싱 결과는 복사본처럼 동작합니다. 예전에는 슬라이스가 뷰인지 복사인지 예측할 수 없어 SettingWithCopyWarning이 떴는데, 그 경고 자체가 사라졌습니다. 대신 연쇄 할당(chained assignment)은 이제 조용히 아무 일도 하지 않습니다.

예시 코드

df = pd.DataFrame({"a": [1, 2, 3], "b": [4, 5, 6]})

sub = df[df["a"] > 1]     # 예전엔 .copy()를 붙여야 했던 자리
sub.loc[:, "b"] = 0        # 원본 df는 절대 안 바뀜
print(df["b"].tolist())

df["a"][0] = 99            # 연쇄 할당 → 반영되지 않음(경고도 없음)
print(df["a"].tolist())

df.loc[0, "a"] = 99        # 올바른 방법: 한 번의 .loc 호출
print(df["a"].tolist())
[4, 5, 6] [1, 2, 3] [99, 2, 3]
기존 코드에서 df[col][row] = value 나 df[df.x > 0]["y"] = 1 같은 패턴이 있다면 지금 전부 실패하고 있습니다. 예외도 경고도 없이 값만 안 바뀝니다. df.loc[행조건, "열"] = 값 한 줄로 바꾸세요.
