먼저 알아야 할 4가지

개별 함수를 외우기 전에 이 네 가지를 이해하면 나머지는 대부분 유추됩니다. NumPy에서 나는 버그의 90%는 축(axis), 브로드캐스팅, 뷰/복사, dtype에서 나옵니다.

① 축(axis) — "어느 방향으로 접을 것인가"

axis는 "그 축이 사라지는 방향"으로 기억하세요. (2,3) 배열에 sum(axis=0)을 하면 0번 축(길이 2)이 사라져 (3,)이 됩니다. 행이 사라졌으니 세로로 접은 것이고, 결과는 열별 합계입니다.

예시 코드

# 축을 지정하지 않으면 전체를 하나로 접는다
s = np.array([[1, 2, 3], [4, 5, 6]])
print(np.sum(s))            # 스칼라
print(np.sum(s, axis=0))    # 열별 합계
print(np.sum(s, axis=1))    # 행별 합계
print(np.sum(s, axis=1, keepdims=True))  # 축을 남겨 (2,1)로
21 [5 7 9] [ 6 15] [[ 6] [15]]
keepdims=True는 브로드캐스팅과 짝을 이룹니다. x / x.sum(axis=1, keepdims=True)는 행별 정규화가 되지만, keepdims가 없으면 shape이 어긋나 에러가 나거나 엉뚱한 축으로 나눠집니다.

② 브로드캐스팅 — 반복문 없이 shape 맞추기

shape이 다른 배열끼리 연산할 때, NumPy는 뒤쪽 축부터 비교해서 크기가 같거나 한쪽이 1이면 자동으로 늘려 맞춥니다. 실제로 메모리를 복제하지는 않으므로 공짜에 가깝습니다.

규칙

  • 차원 수가 다르면 앞쪽에 1을 채워 맞춥니다. (3,4) vs (4,) → (3,4) vs (1,4)
  • 각 축에서 크기가 같거나 한쪽이 1이면 통과. 둘 다 1이 아니면서 다르면 ValueError
  • 크기 1인 축은 상대 축 크기만큼 반복된 것처럼 동작합니다

예시 코드

m = np.arange(6).reshape(2, 3)
print(m + 10)                        # 스칼라 브로드캐스팅
print(m * np.array([1, 10, 100]))    # (2,3) * (3,) → 열마다 다른 배율
print(m + np.array([[100], [200]]))  # (2,3) + (2,1) → 행마다 다른 오프셋
[[10 11 12] [13 14 15]] [[ 0 10 200] [ 3 40 500]] [[100 101 102] [203 204 205]]
np.zeros((3,4)) + np.zeros((3,))는 실패합니다. 뒤쪽 축부터 비교하므로 4와 3이 부딪힙니다.
ValueError: operands could not be broadcast together with shapes (3,4) (3,)
행 방향으로 더하고 싶었다면 np.zeros((3,1)) 또는 arr[:, None]으로 축을 명시하세요.

③ 뷰(view)와 복사(copy) — 원본이 같이 바뀌는 이유

기본 슬라이싱·reshape·.T·ravel은 뷰를 돌려줍니다. 같은 메모리를 다른 창으로 보는 것이라 한쪽을 수정하면 다른 쪽도 바뀝니다. 반면 불리언 인덱싱·팬시 인덱싱·flatten·copy는 새 메모리를 만듭니다.

예시 코드

base = np.arange(6)
view = base[::2]        # 슬라이싱 → 뷰
view[0] = 99
print(base)             # 원본이 오염됨

cp = base[::2].copy()   # 명시적 복사
cp[1] = -1
print(base)             # 원본은 그대로
print(np.shares_memory(base, view), view.base is base)
[99 1 2 3 4 5] [99 1 2 3 4 5] True True
함수 인자로 받은 배열을 제자리 수정(arr[mask] = 0, arr += 1)하면 호출자의 배열까지 바뀝니다. 라이브러리성 코드에서는 진입부에서 arr = np.asarray(arr).copy() 또는 np.array(arr)로 방어하세요. 반대로 대용량 파이프라인에서는 뷰를 활용해 복사를 피하는 게 성능의 핵심입니다.

④ dtype — 배열은 타입이 고정돼 있다

파이썬 리스트와 달리 ndarray는 모든 원소가 같은 타입입니다. 이 덕분에 빠르지만, 오버플로와 암묵적 절삭이라는 대가가 따릅니다.

dtype크기범위 / 특징주 용도
int8 / uint81B-128~127 / 0~255이미지 픽셀, 마스크
int324B±21억인덱스, 라벨
int648B정수 기본값(Linux/macOS)일반 정수 연산
float324B유효자릿수 ~7딥러닝 텐서, 대용량
float648B유효자릿수 ~15, 실수 기본값과학 계산 기본
bool1BTrue/False마스크
<U10가변유니코드 고정 길이 문자열라벨명 (길이 초과 시 잘림)

예시 코드

small = np.array([120, 120], dtype=np.int8)
print(small + small)                       # 조용히 오버플로
print(np.array([1, 2], dtype=np.uint8) - np.array([3, 3], dtype=np.uint8))
print(np.array([1.7, -2.9, 3.2]).astype(int))  # 반올림 아니라 0쪽으로 절삭
print(0.1 + 0.2 == 0.3, np.isclose(0.1 + 0.2, 0.3))
[-16 -16] [254 255] [ 1 -2 3] False True
astype(int)은 반올림이 아니라 0 방향 절삭입니다. 반올림을 원하면 np.round(x).astype(int)를 쓰세요. 그리고 실수 비교에는 절대 ==를 쓰지 말고 np.isclose / np.allclose를 사용하세요.

np.array()

복사

리스트·튜플·중첩 시퀀스를 ndarray로 만듭니다. 가장 많이 쓰이는 진입점이며, 기본적으로 입력을 복사합니다.

시그니처

np.array(object, dtype=None, *, copy=True, order='K', subok=False, ndmin=0)

파라미터

파라미터설명기본값 / 옵션
object 필수배열로 변환할 대상. 리스트, 튜플, 다른 ndarray, __array__를 구현한 객체—
dtype원소 타입을 강제. 생략하면 입력에서 가장 넓은 타입으로 추론None / np.float32, int, 'U10' …
copy복사 여부. NumPy 2.0부터 False는 "복사 불가하면 에러"라는 뜻으로 의미가 바뀜True / False, None(가능하면 복사 회피)
order메모리 배치. C=행 우선, F=열 우선'K' / 'C', 'F', 'A'
ndmin결과의 최소 차원 수. 1D를 강제로 2D로 올릴 때0

예시 코드

import numpy as np

arr = [1, 2, 3]
a = np.array(arr)
print(a, a.dtype, a.shape)

b = np.array([[1, 2], [3, 4]], dtype=np.float32)
print(b, b.dtype)
[1 2 3] int64 (3,) [[1. 2.] [3. 4.]] float32
중첩 리스트의 길이가 들쭉날쭉하면([[1,2],[3]]) NumPy 2.x에서는 ValueError입니다. 예전처럼 object 배열로 조용히 넘어가지 않습니다. 의도한 것이라면 dtype=object를 명시하세요.

ndarray.astype()

복사

dtype을 바꾼 새 배열을 만듭니다. float32 변환으로 메모리를 절반으로 줄이는 건 대용량 처리의 기본기입니다.

시그니처

ndarray.astype(dtype, order='K', casting='unsafe', subok=True, copy=True)

파라미터

파라미터설명기본값 / 옵션
dtype 필수목표 타입np.float32, 'int32', bool …
casting허용할 변환 강도. 'safe'는 정보 손실이 있으면 에러'unsafe' / 'safe', 'same_kind'
copyFalse면 타입이 이미 같을 때 복사 생략True

예시 코드

f = np.array([1.7, -2.9, 3.2])
print(f.astype(int))     # 0 방향 절삭
