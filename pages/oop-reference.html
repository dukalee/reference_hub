먼저 알아야 할 4가지

개별 문법을 외우기 전에 이 네 가지를 이해하면 나머지는 대부분 유추됩니다. Python OOP 코드를 읽다 막히는 지점의 대부분은 클래스/인스턴스 구분, 상속 순서(MRO), 상속과 컴포지션의 선택, 매직 메소드 호출 시점에서 나옵니다.

① 클래스 vs 인스턴스 — "설계도"와 "실체"

클래스는 속성과 동작을 정의하는 설계도이고, 인스턴스는 그 설계도로 찍어낸 실체입니다. 인스턴스 속성(self.x = ...)은 각 인스턴스마다 독립적이지만, 인스턴스에 없는 속성을 찾을 때는 클래스로 거슬러 올라가 공유합니다.

예시 코드

class Dog:
    species = "Canis familiaris"   # 클래스 속성 — 모든 인스턴스가 공유
    def __init__(self, name):
        self.name = name              # 인스턴스 속성 — 각자 따로

d1 = Dog("Rex")
d2 = Dog("Milo")
print(d1.name, d2.name, d1.species, d2.species)
Dog.species = "canine"              # 클래스 속성 변경 → 전부 반영
print(d1.species, d2.species)
d1.species = "wolf-like"            # d1에만 새 인스턴스 속성 생성(가림)
print(d1.species, d2.species, Dog.species)
Rex Milo Canis familiaris Canis familiaris canine canine wolf-like canine canine
클래스 속성으로 리스트·딕셔너리 같은 가변 객체를 두면 함정이 됩니다. class Dog: tricks = [] 라고 쓰면 모든 인스턴스가 같은 리스트를 공유해서 한 마리가 배운 재주가 다른 개에게도 나타납니다. 인스턴스별로 필요하면 __init__에서 만드세요.

② MRO(Method Resolution Order) — 상속이 여러 갈래일 때 찾는 순서

메소드를 호출하면 파이썬은 인스턴스 → 클래스 → 부모 클래스 순으로 C3 선형화 알고리즘이 정한 순서를 따라 찾습니다. 다중상속에서 "누구 메소드가 실행되는가"는 항상 MRO로 결정됩니다.

예시 코드

class A:
    def greet(self): return "A"
class B(A):
    def greet(self): return "B->" + super().greet()
class C(A):
    def greet(self): return "C->" + super().greet()
class D(B, C):
    def greet(self): return "D->" + super().greet()

print(D().greet())
print([k.__name__ for k in D.__mro__])
D->B->C->A ['D', 'B', 'C', 'A', 'object']
super()는 "부모 클래스"가 아니라 MRO 상에서 다음 클래스를 가리킵니다. 다이아몬드 상속에서 B와 C가 각각 super().greet()을 부르면 A가 한 번만 실행되는 이유입니다(협력적 다중상속, cooperative multiple inheritance).

③ 컴포지션 vs 상속 — "이다(is-a)" vs "가지고 있다(has-a)"

상속은 "~은 ~이다" 관계(Car는 Vehicle이다)에만 쓰세요. 부품을 조립하는 관계(Car는 Engine을 가지고 있다)는 컴포지션으로 표현합니다. "Favor composition over inheritance"는 GoF 디자인 패턴에서부터 내려오는 원칙으로, 상속 계층이 깊어질수록 결합도가 높아져 유지보수가 어려워지기 때문입니다.

예시 코드

class Engine:
    def start(self): return "엔진 시동"

class Car:                    # 상속 대신 컴포지션
    def __init__(self):
        self.engine = Engine()   # Car는 Engine을 "가지고" 있다
    def start(self):
        return self.engine.start()   # 위임(delegation)

print(Car().start())
엔진 시동
엔진을 ElectricEngine으로 바꾸고 싶으면 Car 코드를 건드리지 않고 생성자에 다른 객체만 주입하면 됩니다(의존성 주입). 상속으로 ElectricCar(Car)를 만들면 Car의 불필요한 메소드까지 전부 물려받고, 나중에 엔진 타입을 바꾸기 어렵습니다.

④ 매직 메소드가 호출되는 시점

매직(던더, dunder) 메소드는 직접 호출하지 않고 파이썬 문법이나 내장 함수가 대신 호출합니다. 어떤 문법이 어떤 메소드를 부르는지 표로 익혀두면 연산자 오버로딩 코드를 읽기 훨씬 쉬워집니다.

작성한 코드실제로 호출되는 메소드
Vec(3) + Vec(4)Vec(3).__add__(Vec(4))
len(obj)obj.__len__()
obj[key] / obj[key] = vobj.__getitem__(key) / __setitem__
for x in obj:iter(obj) → obj.__iter__(), 매 반복마다 __next__()
print(obj) / f"{obj}"obj.__str__() (없으면 __repr__로 대체)
obj()obj.__call__()
a == ba.__eq__(b)
with obj:obj.__enter__() / obj.__exit__()

예시 코드

class Vec:
    def __init__(self, x): self.x = x
    def __add__(self, other): return Vec(self.x + other.x)
    def __repr__(self): return f"Vec({self.x})"
    def __len__(self): return self.x

v = Vec(3) + Vec(4)   # 내부적으로 Vec(3).__add__(Vec(4))
print(v, len(v))       # len(v) → v.__len__()
Vec(7) 7

클래스 정의·인스턴스화

5 concepts

모든 OOP 코드는 여기서 시작합니다. 상위 3개가 전부 이 섹션에 있습니다.

#01

class 정의

속성과 메소드를 하나로 묶는 사용자 정의 타입을 만듭니다. 클래스 몸체는 정의 시점에 한 번 실행되어 클래스 네임스페이스를 채웁니다.

시그니처

class ClassName(Base1, Base2, ...): "docstring" <클래스 속성 / 메소드 정의>

예시 코드

class Dog:
    """개 한 마리를 표현하는 클래스"""
    def __init__(self, name, age):
        self.name = name
        self.age = age
    def bark(self):
        return f"{self.name}: 멍멍!"

rex = Dog("Rex", 3)
print(rex.bark())
print(type(rex), isinstance(rex, Dog))
Rex: 멍멍! <class '__main__.Dog'> True
파이썬 클래스명은 관례상 PascalCase를 씁니다. 함수·변수는 snake_case인 것과 대비됩니다 (PEP 8).
#02

__init__()

생성자

인스턴스가 만들어진 직후 자동으로 호출되어 초기 상태를 설정합니다. 값을 반환하지 않으며(항상 None), 반환문을 쓰면 TypeError가 납니다.

시그니처

def __init__(self, ...): self.attr = value

예시 코드

class Point:
    def __init__(self, x=0, y=0):
        self.x = x
        self.y = y

p1 = Point()
p2 = Point(3, 4)
print(p1.x, p1.y, p2.x, p2.y)
print(p1 is p2, p1.__dict__)
0 0 3 4 False {'x': 0, 'y': 0}
인스턴스의 모든 속성은 보통 __dict__라는 딕셔너리에 저장됩니다. vars(obj)도 같은 값을 돌려줍니다 — 디버깅 시 print(obj.__dict__)가 유용합니다.
#03

self

인스턴스 메소드의 첫 번째 매개변수로, 호출한 인스턴스 자신이 자동으로 전달됩니다. obj.method(a)는 내부적으로 ClassName.method(obj, a)와 같습니다.

예시 코드

class Counter:
    def __init__(self):
        self.n = 0
    def inc(self):
        self.n += 1
        return self.n

c = Counter()
print(c.inc(), c.inc())      # c.inc() == Counter.inc(c)
bound = c.inc                 # 바운드 메소드: self가 이미 고정됨
print(bound())
print(Counter.inc(c))         # 클래스에서 직접 부르면 self를 명시
1 2 3 4
self는 예약어가 아니라 관례입니다. 다른 이름을 써도 동작하지만, PEP 8과 모든 파이썬 코드베이스가 self를 쓰므로 반드시 지키세요.

인스턴스 속성 vs 클래스 속성

클래스 속성은 모든 인스턴스가 공유하고, 인스턴스 속성은 self.attr = ...로 인스턴스마다 독립적으로 만들어집니다. 인스턴스에 같은 이름으로 대입하면 클래스 속성을 가리는(shadow) 새 인스턴스 속성이 생깁니다.

예시 코드

class Robot:
    population = 0            # 클래스 속성 — 전체 개체 수 카운터
    def __init__(self, name):
        self.name = name          # 인스턴스 속성
        Robot.population += 1

r1 = Robot("R1")
r2 = Robot("R2")
print(Robot.population, r1.population, r2.population)
r1.population = 99            # r1에만 새 인스턴스 속성 생성
print(r1.population, r2.population, Robot.population)
2 2 2 99 2 2
r1.population += 1처럼 보이는 코드도 사실은 "읽고 → 인스턴스에 새로 쓰기"라서 클래스 속성을 변경하지 않습니다. 진짜 클래스 속성을 바꾸려면 Robot.population += 1처럼 클래스 이름으로 접근해야 합니다.

__new__() vs __init__()

__new__가 먼저 호출되어 인스턴스를 실제로 생성하고(정적 메소드, 반환값 있음), 그 인스턴스를 받아 __init__이 초기화합니다(반환값 없음). 보통은 __new__를 건드릴 일이 없지만, 싱글톤이나 불변 타입 서브클래싱에는 필수입니다.

예시 코드

class Singleton:
    _instance = None
    def __new__(cls):
        if cls._instance is None:
            print("새 인스턴스 생성")
            cls._instance = super().__new__(cls)
        return cls._instance
    def __init__(self):
        print("init 호출됨")   # __new__ 성공 후 매번 호출됨

s1 = Singleton()
s2 = Singleton()
print(s1 is s2)
새 인스턴스 생성 init 호출됨 init 호출됨 True
__new__가 해당 클래스의 인스턴스를 반환하지 않으면 __init__은 자동으로 스킵됩니다. 팩토리 함수처럼 다른 타입을 돌려주고 싶을 때 쓰는 패턴입니다.

상속·super()

4 concepts

"is-a" 관계를 코드로 표현하는 방법과, 부모 메소드를 안전하게 재사용하는 super()를 다룹니다.

#04

기본 상속 class Child(Base)

부모 클래스의 속성·메소드를 그대로 물려받고, 필요한 부분만 재정의(오버라이드)합니다. 자식은 부모가 할 수 있는 모든 곳에 쓸 수 있어야 한다는 리스코프 치환 원칙을 지키는 게 좋은 설계입니다.

예시 코드

class Animal:
    def __init__(self, name):
        self.name = name
    def speak(self):
        return "..."

class Cat(Animal):          # Cat은 Animal이다
    def speak(self):        # 오버라이딩
        return f"{self.name}: 야옹"

c = Cat("나비")
print(c.speak())
print(isinstance(c, Animal), issubclass(Cat, Animal))
나비: 야옹 True True
#05

super()

부모(정확히는 MRO 상 다음) 클래스의 메소드를 호출합니다. __init__을 재정의할 때 부모의 초기화 로직을 중복 작성하지 않고 재사용하는 데 가장 많이 쓰입니다.

시그니처

super().method(...) # 파이썬 3, 인자 없이 사용 super(ThisClass, self).method(...) # 명시적 형태(구버전 호환)

예시 코드

class Base:
    def __init__(self, name):
        self.name = name
        print("Base.__init__")

class Derived(Base):
    def __init__(self, name, extra):
        super().__init__(name)   # 부모 초기화 위임
        self.extra = extra
        print("Derived.__init__")

d = Derived("x", 1)
print(d.name, d.extra)
Base.__init__ Derived.__init__ x 1
super().__init__()을 빼먹으면 부모가 설정하는 속성이 없어서 나중에 AttributeError가 납니다. __init__을 오버라이드할 때는 특별한 이유가 없는 한 맨 처음에 호출하세요.

메소드 오버라이딩

같은 이름의 메소드를 자식 클래스에서 다시 정의하면 자식 인스턴스에서는 자식 버전이 우선 실행됩니다. 부모의 동작을 완전히 대체할 수도, super()로 확장할 수도 있습니다.

예시 코드

class Shape:
    def area(self):
        raise NotImplementedError
    def describe(self):
        return f"넓이는 {self.area()}"   # 하위 클래스의 area()를 부른다

class Square(Shape):
    def __init__(self, side):
        self.side = side
    def area(self):
        return self.side ** 2

print(Square(4).describe())
넓이는 16
describe()는 자신이 어떤 도형인지 몰라도 됩니다 — 이것이 다형성(polymorphism)입니다. 이 패턴을 템플릿 메소드 패턴이라고 부릅니다.

다중상속과 MRO 재확인

클래스가 부모를 둘 이상 가지면(class D(B, C)) 메소드 탐색 순서는 D.__mro__로 항상 확인할 수 있습니다. 순서는 "왼쪽 부모 우선, 그러나 공통 조상은 맨 마지막"이라는 C3 규칙을 따릅니다.

예시 코드

class A:
    def greet(self): return "A"
class B(A):
    def greet(self): return "B"
class C(A):
    def greet(self): return "C"
class D(B, C):
    pass

print(D().greet())                          # B가 C보다 먼저
print([k.__name__ for k in D.__mro__])
B ['D', 'B', 'C', 'A', 'object']
MRO가 모순되어 계산이 불가능하면(예: 부모 순서가 서로 충돌) 클래스 정의 시점에 TypeError: Cannot create a consistent method resolution order가 발생합니다.

#07

__repr__()

객체의 공식적인 문자열 표현을 돌려줍니다. REPL·디버거·repr()·리스트 안 원소 출력에 쓰이며, 가능하면 eval(repr(obj)) == obj가 성립하도록(또는 최소한 명확하도록) 작성하는 게 관례입니다.

시그니처

def __repr__(self) -> str: ...

예시 코드

class Point:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f"Point(x={self.x}, y={self.y})"

p = Point(1, 2)
print(p)          # __str__이 없으면 __repr__로 대체
print([p])        # 리스트 안 원소는 항상 repr()
print(repr(p))
Point(x=1, y=2) [Point(x=1, y=2)] Point(x=1, y=2)
__repr__을 정의하지 않으면 기본값은 <__main__.Point object at 0x...>처럼 메모리 주소만 보여줘 디버깅에 쓸모가 없습니다. 모든 클래스에 __repr__은 기본으로 넣는 게 좋은 습관입니다.
#11

__str__()

객체의 사용자 친화적 문자열 표현입니다. print(), str(), f-string에서 우선적으로 호출되고, 정의되어 있지 않으면 __repr__로 대체됩니다.

예시 코드

class Point2:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __repr__(self):
        return f"Point2({self.x!r}, {self.y!r})"   # 개발자용, 명확하게
    def __str__(self):
        return f"({self.x}, {self.y})"              # 사용자용, 간결하게

p2 = Point2(1, 2)
print(p2)                 # __str__ 사용
print(str(p2), repr(p2))
print(f"위치: {p2}")      # f-string도 __str__ 사용

__eq__() · __hash__()

__eq__는 == 비교를 정의합니다(기본값은 is와 동일한 정체성 비교). __eq__를 직접 정의하면 기본 __hash__가 자동으로 사라져 해시 불가능한 객체가 되므로, 딕셔너리 키나 집합 원소로 쓰려면 __hash__도 같이 정의해야 합니다.

예시 코드

class Money:
    def __init__(self, amount, currency):
        self.amount, self.currency = amount, currency
    def __eq__(self, other):
        if not isinstance(other, Money):
            return NotImplemented
        return (self.amount, self.currency) == (other.amount, other.currency)
    def __hash__(self):
        return hash((self.amount, self.currency))

m1 = Money(1000, "KRW")
m2 = Money(1000, "KRW")
print(m1 == m2, m1 is m2)   # 값이 같으면 == True, 서로 다른 객체
print(len({m1, m2}))       # set은 __eq__+__hash__ 기준으로 중복 제거
True False 1
__eq__에서 타입이 다르면 False가 아니라 NotImplemented를 반환하세요. 그래야 파이썬이 상대 타입의 __eq__(예: other.__eq__(self))도 시도해볼 기회를 줍니다.

산술 연산자 __add__ · __mul__ · __rmul__

+, -, * 등은 각각 __add__, __sub__, __mul__을 호출합니다. 왼쪽 피연산자에 해당 메소드가 없거나 NotImplemented를 반환하면, 오른쪽 피연산자의 __radd__ 같은 "반사" 메소드를 시도합니다.

예시 코드

class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y
    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)
    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)
    def __rmul__(self, scalar):     # scalar * self 형태를 지원
        return self.__mul__(scalar)
    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

v1, v2 = Vector(1, 2), Vector(3, 4)

print(v1 * 3)

비교 연산자 __lt__ · functools.total_ordering

<, <=, >, >=는 각각 별도의 메소드입니다. @functools.total_ordering을 쓰면 __eq__와 하나(__lt__ 권장)만 정의해도 나머지를 자동으로 채워줍니다.

예시 코드

from functools import total_ordering

@total_ordering
class Version:
    def __init__(self, major, minor):
        self.major, self.minor = major, minor
    def __eq__(self, other):
        return (self.major, self.minor) == (other.major, other.minor)
    def __lt__(self, other):
        return (self.major, self.minor) < (other.major, other.minor)
    def __repr__(self):
        return f"v{self.major}.{self.minor}"

versions = [Version(1, 2), Version(1, 0), Version(2, 0)]
print(sorted(versions))          # sort는 내부적으로 __lt__만 사용
print(Version(1, 0) <= Version(1, 2))   # total_ordering이 자동 생성

__iter__() · __next__()

이터레이터

for x in obj:는 먼저 iter(obj)(→ __iter__)를 호출해 이터레이터를 얻고, 매 반복마다 next()(→ __next__)를 호출합니다. 더 줄 값이 없으면 StopIteration을 발생시켜 반복을 끝냅니다.

예시 코드

class Countdown:
    def __init__(self, start):
        self.start = start
    def __iter__(self):
        self.cur = self.start
        return self             # self 자신이 이터레이터 역할도 겸함
    def __next__(self):
        if self.cur <= 0:
            raise StopIteration
        self.cur -= 1
        return self.cur + 1

print(list(Countdown(3)))
for n in Countdown(2):
    print("tick", n)
[3, 2, 1] tick 2 tick 1
간단한 이터레이터는 클래스보다 제너레이터 함수(yield)로 만드는 게 훨씬 짧습니다. __iter__/__next__를 직접 구현하는 건 상태를 세밀히 제어해야 하거나 __len__ 같은 다른 프로토콜과 결합할 때가 많습니다.

class Circle:

class Temperature:

    def celsius(self):

    @celsius.deleter
    def celsius(self):
        print("celsius 삭제됨")
        del self._celsius

t.celsius = 30
print(t.celsius)
try:
    t.celsius = -300
except ValueError as e:

del t.celsius

예시 코드

class PositiveNumber:               # 디스크립터
    def __set_name__(self, owner, name):
        self.name = "_" + name
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)
    def __set__(self, obj, value):
        if value <= 0:
            raise ValueError(f"{self.name}는 양수여야 함")
        setattr(obj, self.name, value)

class Product:
    price = PositiveNumber()                # 클래스 속성으로 배치
    def __init__(self, price):
        self.price = price                  # → PositiveNumber.__set__ 호출

p = Product(1000)
print(p.price)                              # → PositiveNumber.__get__ 호출
try:
    p.price = -5

#10

@classmethod

첫 번째 인자로 인스턴스 대신 클래스 자신(cls)을 받습니다. 대안 생성자(팩토리 메소드)를 만들 때 가장 많이 쓰이며, cls(...)로 인스턴스를 만들면 서브클래스에서도 올바른 타입이 생성됩니다.

class Pizza:

    def margherita(cls):

        return f"{type(self).__name__}({self.toppings})"

@staticmethod

self도 cls도 받지 않는 일반 함수를 클래스 네임스페이스 안에 넣습니다. 클래스와 논리적으로만 연관된 도우미 함수(순수 유틸리티)를 그룹화할 때 씁니다.

예시 코드

class MathUtils:

print(MathUtils.is_even(4), MathUtils.clamp(15, 0, 10))

classmethod 레지스트리 팩토리 패턴

@classmethod와 클래스 딕셔너리를 결합하면 이름으로 서브클래스를 등록·조회하는 플러그인 시스템을 간단히 만들 수 있습니다.

예시 코드

class Shape:
    _registry = {}
    @classmethod
    def register(cls, name):
        def deco(subclass):
            cls._registry[name] = subclass
            return subclass
        return deco
    @classmethod
    def create(cls, name, *args):
        return cls._registry[name](*args)

@Shape.register("circle")
class CircleShape(Shape):
    def __init__(self, r):
        self.r = r
    def __repr__(self):
        return f"CircleShape(r={self.r})"

인스턴스 생성 후 필드 재할당을 막아 불변(immutable) 객체로 만듭니다. 값이 같으면 __hash__도 자동 생성되어(기본 dataclass는 eq=True일 때 __hash__=None이 되는 것과 대조적으로) 딕셔너리 키·집합 원소로 쓸 수 있습니다.

예시 코드

@dataclass(frozen=True)
class ImmutablePoint:
    x: int
    y: int

ip = ImmutablePoint(1, 2)

try:
    ip.x = 5
except Exception as e:
    print(type(e).__name__, e)

@dataclass

    height: float

#15

abc.ABC를 상속하고 @abstractmethod를 붙인 메소드가 있으면, 그 메소드를 전부 구현하지 않은 서브클래스는 인스턴스화 시점에 TypeError가 납니다. 인터페이스를 문서화하는 데 그치지 않고 강제합니다.

예시 코드

#19

issubclass(A, B)는 A가 B를 상속했는지 확인합니다. ABC의 register()를 쓰면 상속 관계 없이도 특정 클래스를 "가상 서브클래스"로 등록해 isinstance/issubclass를 통과시킬 수 있습니다.

예시 코드

class Duck:
    def quack(self): return "꽥"

class Flyer(ABC):
    @abstractmethod
    def fly(self): ...

Flyer.register(Duck)   # Duck은 Flyer를 상속하지 않았지만 등록

믹스인(Mixin) 패턴

단독으로는 쓰이지 않고, 다른 클래스에 기능 한 조각을 얹기 위해서만 다중상속되는 클래스입니다. 이름 관례상 ~Mixin으로 끝내고, 보통 자체 __init__이나 상태를 갖지 않습니다.

class JsonMixin:
    def to_json(self):
        import json
        return json.dumps(self.__dict__, ensure_ascii=False)

class LogMixin:
    def log(self, msg):
        print(f"[{type(self).__name__}] {msg}")

class User(JsonMixin, LogMixin):   # 두 기능을 조합
    def __init__(self, name):
        self.name = name

u = User("gemma")
print(u.to_json())
u.log("생성됨")

다중상속과 이름 충돌

두 부모가 같은 이름의 메소드를 가지면 MRO 순서(왼쪽 부모 우선)로 승자가 결정됩니다. 조용히 한쪽이 무시되므로, 믹스인을 조합할 때는 메소드 이름이 겹치지 않도록 설계하는 게 안전합니다.

예시 코드

class Base1:
    def greet(self): return "Base1"
class Base2:
    def greet(self): return "Base2"
class Multi(Base1, Base2):
    pass

print(Multi().greet())   # Base1이 이긴다 — 왼쪽이 우선
print([k.__name__ for k in Multi.__mro__])

이런 충돌은 예외를 던지지 않고 조용히 결정되므로 디버깅이 까다롭습니다. 다중상속을 쓸 때는 ClassName.__mro__를 확인하는 습관을 들이세요.

Composition over inheritance 다시 보기

"조합 가능한 여러 기능"이 필요하면 믹스인(다중상속)도 방법이지만, 부품들이 런타임에 교체 가능해야 한다면 컴포지션이 낫습니다. 둘 다 "여러 기능을 조립한다"는 목적은 같지만 결합 강도가 다릅니다.

프로토콜·구조적 타이핑

3 concepts

"이 타입을 상속해야 한다"가 아니라 "이 메소드/속성만 있으면 된다"는 덕 타이핑을 typing 모듈로 정적 타입 체커에게도 알려주는 방법입니다.

#22

typing.Protocol

상속 없이 "이런 메소드를 가진 타입"이라는 인터페이스를 정의합니다. mypy 같은 정적 타입 체커가 구조(메소드 시그니처)만 보고 호환 여부를 판단하게 해줍니다 — 런타임 동작은 순수 덕 타이핑과 같습니다.

예시 코드

from typing import Protocol

class SupportsArea(Protocol):
    def area(self) -> float: ...

class Circle:                     # SupportsArea를 상속하지 않는다
    def __init__(self, r): self.r = r
    def area(self): return 3.14 * self.r ** 2

def total_area(shapes: list) -> float:
    return sum(s.area() for s in shapes)   # area()만 있으면 뭐든 통과

print(total_area([Circle(1), Circle(2)]))
15.700000000000001
Circle은 SupportsArea를 상속하지 않았지만 area() 메소드 시그니처가 맞기 때문에 mypy는 total_area에 넘겨도 안전하다고 판단합니다. ABC는 명목적(nominal) 타이핑, Protocol은 구조적(structural) 타이핑입니다.

@runtime_checkable

기본적으로 Protocol은 isinstance() 검사에 쓸 수 없습니다(정적 분석 전용). @runtime_checkable을 붙이면 메소드 존재 여부만(시그니처는 검사하지 않음) 런타임에 확인할 수 있게 됩니다.

예시 코드

from typing import Protocol, runtime_checkable

@runtime_checkable
class HasName(Protocol):
    name: str

class Person:
    def __init__(self, name): self.name = name

print(isinstance(Person("kim"), HasName))
print(isinstance(42, HasName))
True False
runtime_checkable 검사는 속성이 있는지만 확인하고 타입까지는 검증하지 않습니다. name이 int여도 isinstance 통과가 가능합니다 — 정적 타입 체커의 엄격함을 기대하면 안 됩니다.

덕 타이핑 — "오리처럼 걷고 오리처럼 운다면"

파이썬은 기본적으로 타입보다 동작을 봅니다. 공통 부모나 Protocol 선언 없이도 필요한 메소드만 있으면 같은 함수에 넘길 수 있습니다 — ABC/Protocol은 이 유연함에 명시적 계약을 얹는 선택지일 뿐입니다.

예시 코드

class Duck2:
    def sound(self): return "꽥꽥"
class Dog2:
    def sound(self): return "멍멍"

def make_sound(animal):     # 타입 힌트도, 공통 부모도 없다
    return animal.sound()

print([make_sound(a) for a in [Duck2(), Dog2()]])
['꽥꽥', '멍멍']
소규모 스크립트에서는 덕 타이핑만으로 충분합니다. 팀 규모가 커지거나 IDE 자동완성·정적 검사가 중요해지면 Protocol을, "반드시 구현을 강제"해야 하면 ABC를 선택하세요.

메타클래스

3 concepts

"클래스도 객체다" — 그리고 그 객체를 만드는 것이 메타클래스입니다. 실무에서 직접 쓸 일은 드물지만 Django ORM·SQLAlchemy·ABC 자체가 이 메커니즘 위에 서 있습니다.

type()으로 클래스 직접 만들기

파이썬에서 클래스 자체도 객체이고, 그 객체를 만드는 클래스가 type입니다. class 문은 결국 type(name, bases, namespace)를 호출하는 문법 설탕입니다.

예시 코드

def init(self, x): self.x = x

Dynamic = type(
    "Dynamic",                                  # 클래스 이름

#25

커스텀 메타클래스 metaclass=

type을 상속해 클래스가 정의되는 시점의 동작을 가로챌 수 있습니다. 클래스 생성 시 자동으로 속성을 검증하거나 변형하는 프레임워크 코드(ORM 필드 수집 등)에 쓰입니다.

예시 코드

class UpperAttrMeta(type):        # type을 상속
    def __new__(mcs, name, bases, namespace):
        upper_ns = {
            (k.upper() if not k.startswith("__") else k): v
            for k, v in namespace.items()
        }
        return super().__new__(mcs, name, bases, upper_ns)

class Config(metaclass=UpperAttrMeta):
    debug = True
    version = "1.0"

print(Config.DEBUG, Config.VERSION)   # 속성명이 대문자로 바뀌었다
print(hasattr(Config, "debug"))
True 1.0 False
메타클래스는 강력하지만 "다음에 이걸 읽을 사람이 이해할 수 있는가"를 항상 먼저 물으세요. __init_subclass__나 클래스 데코레이터로 같은 목적을 더 쉽게 달성할 수 있는 경우가 많습니다.

__init_subclass__()

메타클래스 없이도 "이 클래스가 상속될 때마다 실행할 로직"을 넣을 수 있는 더 가벼운 대안입니다. 서브클래스 자동 등록, 필수 속성 검증 같은 메타클래스의 흔한 용도 상당수를 대체합니다.

예시 코드

class Plugin:
    registry = []
    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry.append(cls.__name__)   # 상속될 때마다 자동 등록

class PluginA(Plugin): pass
class PluginB(Plugin): pass
print(Plugin.registry)
['PluginA', 'PluginB']
"메타클래스가 필요한가?"라는 질문에는 대부분 __init_subclass__(클래스 생성 훅) 또는 클래스 데코레이터로 충분하다는 답이 나옵니다. 메타클래스는 메타클래스끼리도 충돌할 수 있어(두 부모가 다른 메타클래스를 쓰면 TypeError) 정말 필요할 때만 쓰세요.

실무 레시피

4 recipes

여러 개념을 조합해 실무에서 자주 마주치는 패턴을 구현하는 방법입니다.

싱글톤 패턴

클래스당 인스턴스를 정확히 하나만 만들도록 강제합니다. 설정 객체, 로거, DB 커넥션 풀처럼 전역에서 하나만 있어야 하는 자원에 씁니다. __new__를 재정의하는 것이 가장 일반적인 구현입니다.

예시 코드

class Singleton:
    _instances = {}
    def __new__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__new__(cls)
        return cls._instances[cls]

class Logger(Singleton):
    pass

print(Logger() is Logger())
True
모듈 레벨 전역 변수 하나로도 같은 효과를 훨씬 간단히 낼 수 있습니다 — 파이썬 모듈은 프로세스당 한 번만 임포트되므로 사실상 싱글톤입니다. 클래스 기반 싱글톤은 지연 초기화나 상속 계층이 필요할 때만 고려하세요.

functools.cached_property

캐시

처음 접근할 때 딱 한 번 계산하고, 결과를 인스턴스 __dict__에 저장해 이후 접근은 재계산 없이 돌려줍니다. 비용이 큰 계산인데 값이 자주 바뀌지 않을 때 @property 대신 씁니다.

예시 코드

from functools import cached_property

class DataSet:
    def __init__(self, data):
        self.data = data
    @cached_property
    def total(self):
        print("계산 중...")
        return sum(self.data)

ds = DataSet([1, 2, 3, 4])
print(ds.total)   # 계산 실행
print(ds.total)   # 캐시된 값 재사용 — "계산 중..." 안 찍힘
계산 중... 10 10
cached_property는 인스턴스가 해시 불가능해도 되지만 __dict__가 있어야 합니다 — __slots__를 쓰는 클래스에서는 그대로 동작하지 않습니다. 또한 원본 데이터가 바뀌어도 캐시는 갱신되지 않으니, del obj.total로 수동 무효화해야 합니다.

옵저버 패턴 (pub/sub)

상태 변화가 있을 때 등록된 콜백들에게 알림을 보냅니다. GUI 이벤트, 모델 변경 감지, 간단한 이벤트 버스 구현에 자주 쓰이는 패턴입니다.

예시 코드

class Publisher:
    def __init__(self):
        self._subscribers = []
    def subscribe(self, fn):
        self._subscribers.append(fn)
    def notify(self, event):
        for fn in self._subscribers:
            fn(event)

log = []
pub = Publisher()
pub.subscribe(lambda e: log.append(f"수신: {e}"))
pub.notify("주문완료")
print(log)
['수신: 주문완료']

팩토리 패턴 — dict 기반 dispatch

"타입 이름 → 생성 함수/클래스" 매핑을 딕셔너리에 담으면 if/elif 체인 없이 새 타입을 딕셔너리에 한 줄 추가하는 것만으로 확장할 수 있습니다.

예시 코드

class Circle3:
    def __repr__(self): return "Circle3()"
class Square3:
    def __repr__(self): return "Square3()"

SHAPES = {"circle": Circle3, "square": Square3}   # if/elif 대신 딕셔너리
def create_shape(kind):
    return SHAPES[kind]()

print(create_shape("circle"), create_shape("square"))

성능과 함정

4 pitfalls

OOP 코드에서 나는 버그와 성능 저하의 대부분은 이 네 가지 중 하나입니다.

__slots__로 메모리·속도 절약

성능

__dict__ 기반 인스턴스는 속성마다 딕셔너리 엔트리를 만들어 메모리 오버헤드가 있습니다. 수백만 개의 작은 객체(그래프 노드, 파싱 결과 레코드 등)를 만드는 코드라면 __slots__로 상당한 메모리·속도 이득을 볼 수 있습니다.

예시 코드

class WithDict:
    def __init__(self, x): self.x = x
class WithSlots:
    __slots__ = ("x",)
    def __init__(self, x): self.x = x

wd, ws = WithDict(1), WithSlots(1)
print(hasattr(wd, "__dict__"), hasattr(ws, "__dict__"))
True False
대략적인 체감: 인스턴스당 __dict__ 오버헤드가 사라지면서 객체 하나당 수십~백여 바이트 절약되고, 속성 접근도 딕셔너리 조회 대신 고정 오프셋 접근이라 약간 더 빠릅니다. 정확한 수치는 파이썬 버전·플랫폼에 따라 다르므로 실제 워크로드로 측정하세요.

가변 기본 인자 함정

함정

메소드 기본값(def method(self, items=[]))은 클래스/함수 정의 시점에 딱 한 번 만들어지고, 이후 모든 호출이 같은 객체를 공유합니다. dataclass의 field(default_factory=...)가 이 문제를 막기 위해 존재하는 이유이기도 합니다.

예시 코드

def append_bad(item, container=[]):   # 함정: 기본값이 재사용됨
    container.append(item)
    return container

print(append_bad(1))
print(append_bad(2))   # [1]이 사라지지 않고 남아있다

def append_good(item, container=None):   # 올바른 패턴
    if container is None:
        container = []
    container.append(item)
    return container

print(append_good(1))
print(append_good(2))
[1] [1, 2] [1] [2]
클래스 속성으로 가변 객체를 두는 것도 같은 함정입니다(#a 섹션 참고). "기본값이 리스트·딕셔너리·집합이면 일단 의심하라"는 규칙으로 기억하세요.

얕은 복사 vs 깊은 복사

copy.copy()(얕은 복사)는 최상위 객체만 새로 만들고 내부의 가변 객체는 공유합니다. copy.deepcopy()는 내부까지 재귀적으로 전부 복제합니다. 중첩된 리스트·딕셔너리를 가진 객체를 복사할 때는 반드시 어느 쪽이 필요한지 확인하세요.

예시 코드

import copy

class Box:
    def __init__(self, items):
        self.items = items

b1 = Box([1, 2, 3])
b2 = copy.copy(b1)        # 얕은 복사 — items 리스트는 공유
b3 = copy.deepcopy(b1)    # 깊은 복사 — items도 새로 복제
b1.items.append(4)
print(b2.items, b3.items)
[1, 2, 3, 4] [1, 2, 3]

__eq__만 정의하면 해시 불가능해지는 함정

__eq__를 정의하고 __hash__를 정의하지 않으면, 파이썬은 기본 __hash__를 자동으로 None으로 만들어 그 클래스를 딕셔너리 키·set 원소로 쓸 수 없게 만듭니다. 값이 같으면 해시도 같아야 한다는 불변식을 지키기 위한 안전장치입니다.

예시 코드

class BadKey:
    def __init__(self, val):
        self.val = val
    def __eq__(self, other):
        return self.val == other.val   # __hash__는 정의 안 함

try:
    bk = BadKey(1)
    {bk: "x"}
except TypeError as e:
    print("TypeError:", e)
TypeError: cannot use 'BadKey' as a dict key (unhashable type: 'BadKey')
해결책은 상황에 따라 다릅니다 — 값 객체라면 __hash__ = None 대신 @dataclass(frozen=True)로 두 메소드를 한 번에 얻거나, 가변 객체라면 애초에 해시 불가능한 게 올바른 설계일 수 있습니다(가변 객체를 딕셔너리 키로 쓰면 키가 바뀌는 버그가 생기기 쉽습니다).
